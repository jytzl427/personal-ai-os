# 项目系统联动执行计划

## 目标

把项目从“项目资料展示”扩展为一个简洁的项目工作区，并与任务、财务和 AI 管家的计划/复盘上下文连通。

## 设计原则

1. 所有项目仍使用同一个 SQLite 数据库，通过 `project_id` 关联，不为每个项目拆物理数据库。
2. 项目分类沿用现有 `small`、`mid`、`long_term`，分别对应小型、中型/阶段性、长期/大型。
3. 项目计划任务不是待办任务。只有用户明确加入待办后才创建普通任务；加入后两边保持双向同步。
4. 盈利项目使用已有项目字段作为开关，财务收入/支出使用稳定的 `project_id` 关联；项目名称只作为展示标签，不作为历史记录的唯一依据。
5. 删除、归档、管家写入权限沿用现有安全边界；项目任务从待办移除时保留一条轻量进展记录，避免历史完全消失。

## 执行阶段

### A. 数据层

- 新增 `project_task_plans`：项目计划任务、执行日期、状态、对应普通待办任务 ID。
- 新增 `project_activity_logs`：项目进展、任务完成/移除等精简历史。
- 为旧数据库增加 017 迁移，为新数据库同步加入初始表结构。

### B. 服务层

- 项目详情返回计划任务、进展历史、财务收入/支出/净额摘要。
- 项目计划任务支持新增、修改、加入待办、删除。
- 普通待办完成、归档或删除时，自动同步删除项目计划任务，并记录活动。
- 盈利项目自动出现在收入“项目收入”动态分类和快捷按钮中，记账时写入正确 `project_id`。

### C. AI 管家

- `projects_list`、`projects_get` 和每日/阶段计划上下文包含项目计划任务、财务摘要和近期进展。
- 不新增绕过现有安全门禁的高风险写权限；项目推进仍受阶段计划确认约束。

### D. 界面

- 项目总页继续使用画廊。
- 项目详情增加盈利摘要、项目计划任务和进展记录。
- 项目计划任务可选择“加入待办”；未加入待办的计划不会出现在任务数据库。

## 验收标准

- 新建盈利项目后，财务收入分类和快捷按钮自动出现项目名称。
- 通过项目快捷按钮记收入，项目详情净额正确增加；普通支出/收入不改账户余额。
- 未加入待办的项目计划不会出现在普通任务列表；加入后会出现，并且完成/删除普通任务会同步移除项目计划。
- 项目上下文能被计划和复盘读取，且包含客观财务、任务和进展数据。
- 旧数据迁移安全；服务构建、服务器测试和前端构建通过。
