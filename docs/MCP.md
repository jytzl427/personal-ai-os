# MCP contract

生产环境使用发布版 `release/Personal-AI-OS.exe --mcp`。它是一个无界面的直接 MCP 进程：由外部 Agent 自动启动，通过同一个 EXE 打开本机用户数据库，不需要先打开 Web 界面，也不需要启动 `pnpm dev` 或 HTTP 服务。配置 `PAIOS_TOKEN` 为设置页创建的 Agent token。

开发环境仍可使用 `pnpm --filter @paios/server mcp`，它通过 stdio 转发到 `PAIOS_URL`（默认 `http://127.0.0.1:4738`）。两种模式都会发送 Bearer token、标记 Agent transport，并由服务端校验 token 和 scope；MCP 不能直接打开 SQLite 或绕过业务接口。

## Resources

| URI | Meaning |
|---|---|
| `paios://today` | Today summary: tasks, finance, health, plan and pending confirmations |
| `paios://schema/overview` | Entity and tool-scope overview with generation time and timezone |
| `paios://projects/{id}` | One project and its planning context |
| `paios://finance/summary` | Current finance summary |
| `paios://workflow/active` | Active workflow definitions |

- `finance_accounts_list`, `finance_account_entries_list`, `finance_account_entry_create`
- `finance_expenses_list`, `finance_incomes_list`, `finance_summary`, `finance_taxonomy`
- `health_get`, `health_range`, `health_put`, `reviews_list`, `reviews_get`, `reviews_update`, `reviews_daily_generate`, `reviews_period_generate`
- `ideas_list`, `ideas_create`, `ideas_update`, `ideas_promote_to_task`, `confirmations_list`
- `batch_run` (maximum 20 registered tool names with per-tool schema validation; arbitrary REST paths and confirmation approval are forbidden)

The tool names and their input schemas are public contract. Ordinary write tools accept an optional `idempotency_key`; when a request may be retried, reuse the same key, and use a new key only for a new intentional write. Human confirmation is UI-only. Agents must never call an approval endpoint. Plans are drafts until confirmed by the human UI. `due_date` is the task execution date. Recurrence rules are validated and generated by the server; an Agent must not calculate or bulk-create occurrences itself. Agents cannot pause or abandon projects, or finalize reviews. Project status on `projects_update` is limited to `idea`, `planned`, `active` and `done`. Updating a project, writing its workspace, or linking a task to a project is rejected until a confirmed stage plan covers today. Creating an empty project workspace does not require that confirmation. Review finalize snapshots and period-review fallbacks count tasks by `due_date` only.

## Ordinary project, idea, health and review tools

These names are part of the current MCP contract, not a pending UI rewrite:

| Tool | Purpose |
| --- | --- |
| `projects_list` | Read project gallery data |
| `projects_get` | Read one project, workspace, posture and linked tasks |
| `projects_create` | Create an empty project workspace (no stage-plan confirmation required) |
| `projects_update` | Update project planning fields after a confirmed stage plan covers today |
| `project_workspace_update` | Write project goals, situation and notes after that confirmation |
| `ideas_list` | Read ideas, including urgency and processing state |
| `ideas_create` | Create an ordinary idea |
| `health_put` | Write one local-date health record |
| `reviews_list` | Read daily or period reviews |

These tools do not approve confirmation tickets, restore archive records, purge history, alter schema, physically delete data, or finalize reviews. Finance amounts remain integer cents and finance writes should include the validated major/minor taxonomy values. A tool call with an invalid, revoked, missing, or insufficient token is rejected before the business handler runs. There is no separate MCP tool for “加入待办”; that toggle lives in the human project workspace.

## Fixed capability answer

When the user asks what the Butler can do, the Agent must call `capabilities_get` and use its `answer` field as the capability description. It must not improvise a broader permission list. The answer is scope-aware and explicitly states that physical deletion, purge, restore, schema changes and confirmation approval remain unavailable to Agents.

## Safety rules

- Read `system_status` first and verify that `dataDir` is the user's personal `.paios` directory, not the repository `.data` directory.
- Use `today_get` before scheduling or writing a daily record.
- For updates, pass the latest `row_version` when the record provides one. On a version conflict, reread and ask before retrying.
- For periodic tasks, inspect `task_recurrences_list`; create an independent template with `task_recurrence_create` only after the user explicitly requests periodic behavior. A template is not an ordinary task. The server creates ordinary instances and keeps a unique occurrence ledger; never manufacture occurrences in the Agent.
- Updating a template affects future local dates only. Content/title/memo edits preserve the original cadence anchor; rule or start-date edits intentionally start a new cadence from a future local date. Existing generated tasks must never be overwritten. Use `task_recurrence_check` with repair only to let the server fill missing dates; it cannot delete or rewrite user data. Use `task_recurrence_occurrences_list` when explaining generated, skipped, or deleted instances.
- Pausing a template skips its paused dates. Deleting a generated ordinary task leaves a deleted occurrence marker so it is not recreated on the next startup.
- Template deletion is a human-UI-only operation. It stops future generation and hides the template while preserving generated ordinary tasks and the occurrence history; Agents have no delete-template tool.
- For any ordinary write, provide an `idempotency_key` when the client may retry. A repeated key with the same tool reuses the original successful response; a key must not be reused for a different intended change.
- A failed or uncertain response is not permission to repeat a write. Reuse the same idempotency key where the tool supports one, then reread the data.
- If a restore is pending, stop writes and ask the user to restart the graphical workbench; direct MCP is intentionally blocked until the restore state is cleared.
- Before a human-approved restore is applied, close any direct MCP process using the same local data directory. The GUI checks the local MCP ownership marker and refuses to replace the database while that process is still alive.
