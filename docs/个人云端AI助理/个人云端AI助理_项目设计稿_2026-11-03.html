一句话： 核心用 LibreChat（MIT 许可，自带管理后台、强制 2FA、Passkey、MCP 白名单、子代理和定时对话），第一版不加模型网关、不开编程子代理，组件越少攻击面越小。

讨论纪要与决策

截至 2026-11-03 的讨论结论，后续设计以此为准

  1. 安卓端只做 PWA，必要时用 TWA 打包；不给助手任何手机权限。 - 手机只用来下命令和看结果；通知用 ntfy 自建服务器推送。
  2. 电脑端同样只用浏览器，不装客户端，不给助手读写电脑的权限。 - 文件按「文件下载规则」由你在网页上手动点击下载。
  3. 订阅 CLI 只由你本人在自己的服务器上，用官方原版工具登录，不做反代。 - 其他用户一律走按量 API。核实依据见「订阅 CLI 核实结论」。
  4. IP 白名单能挡外人，但挡不住投毒。 - 投毒来自你自己信任并主动拉取的依赖、镜像、网页和文件，白名单管不到。 - 入口改用 Tailscale 或 Cloudflare Access 做身份校验；另外做沙箱隔离、出网白名单、依赖版本锁定、文件扫描。
  5. Claude Code 等本地 agent 工具同样有提示词注入风险。 - Anthropic 安全文档也建议，处理不可信内容时放进虚拟机或容器里运行。 - 在云端一次性沙箱里跑编程任务比在本地电脑直接跑更安全：出事只损失一个可销毁的容器，碰不到你电脑上的文件和登录状态。
  6. 对付黑客入侵后投毒或窃取隐私，防线分两层。 - 第一层防止入侵：入口身份校验、2FA、不开放多余端口、及时更新、锁定版本。 - 第二层限制入侵后的损失：数据加密、密钥分开存放、API 消费上限、异地防删除备份、审计日志和告警。 - AI 的写操作必须由你亲手确认。风险可以压得很低，但做不到零。
  7. 你承诺每周维护一次。 - 每周约 15–20 分钟，另有每月深度检查和出事时的应急清单，见「运维与每周维护」。

模型网关

第一版不单独部署网关：LibreChat 可直接配置 OpenAI 兼容端点、provider: anthropic 原生 Messages 端点，并用 useResponsesApi 走 Responses 接口，三种格式都能覆盖。

到第四阶段引入 New API 时，它只监听内网，作用是三件事：给编程子代理统一一个 Base URL 和子 Key；按渠道和用户设额度；在 Chat、Responses、Messages 之间做协议转换。官方文档标注 Claude 与 Responses 互转质量为 fair，协议独有字段可能丢失，所以核心对话优先走原生协议，转换只给子代理兜底。

编程子代理架构

  1. 核心大脑只能调用一个工具：派发编程任务，参数为仓库、目标、预算、允许的模型。
  2. 派发服务校验：调用者是否管理员、任务类型是否为编程、深度不超过 2 层、预算与并发是否在上限内。
  3. 每个任务启动一个一次性 gVisor 容器，挂载任务专用工作区，出网只经白名单代理。
  4. 容器内执行者按任务选择： - 按量 API：Codex CLI、OpenHands 通过网关调用；Gemini CLI 能否指向自建网关地址：不确定，必要时直连 Google API - 订阅 CLI：只给管理员本人用，官方 CLI 在一次性 gVisor 容器里运行。凭证必须随 CLI 进入该容器，CLI 执行的命令有可能读到它，所以该容器出网只放行官方服务和必要的代码托管，任务结束即销毁，异常时到官网吊销（见 C1、S1）
  5. 子代理可再派发下级子代理，但下级权限不得大于上级，任务树共享一个总预算。
  6. 产出只能是独立分支上的 PR 加一份报告，合并必须人工。

MCP 数据层

  • 用 MCP 官方 SDK 自写一个服务器，Streamable HTTP 传输，只在内网监听，LibreChat 用 allowedAddresses 精确放行。
  • 工具按域拆分：记账、健康作息、习惯、学业、项目任务、灵感；每个域分读工具和写工具。
  • 读工具默认返回汇总，明细需显式参数；返回内容标注为数据而非指令。
  • 写工具全部要求人工确认，修改和删除展示前后差异，一律软删除。
  • 每次调用写审计日志；MCP 服务器用独立数据库账号，只授予所需表权限。

安全设计（核心章节）

  • 个人数据：记账、健康、学业、项目、对话历史
  • 模型 API Key 与账单
  • 订阅 CLI 登录凭证

  • 网页、文件、工具返回里的注入内容
  • 被投毒的上游包、镜像、插件
  • 被盗的用户账号或手机
  • 失控的 AI 自身（误操作、无限循环）

红线

以下任一条做不到，就不做对应功能；涉及核心的，整个项目不做： 宁可少功能，不留无法控制的风险。

  1. 无法强制 2FA 或无法关闭公开注册：整个项目不上线。
  2. 管理后台或数据库必须暴露在公网才能用：不上线。
  3. 模型 API 没有硬上限或预付费方式：不接入该供应商。
  4. 编程沙箱做不到出网白名单和 gVisor 级隔离：不做编程子代理。
  5. 订阅 CLI 的用法与其服务条款冲突（如 Claude 订阅 OAuth 用于第三方工具）：不用订阅，改用 API Key。
  6. 订阅需要给其他用户共用：不做。
  7. AI 写个人数据无法做到人工确认和审计：MCP 只开只读。
  8. 无法做异地、加密、防删除（append-only 或版本保留）的备份并验证能恢复：不迁入个人数据。
  9. 告警只能发到被监控的同一台服务器、没有外部监控：不上线。
  10. 安卓端需要敏感权限或设备控制能力：不做该功能。

订阅 CLI 核实结论

场景：本人在自己的海外 VPS 上用官方 CLI 正常登录自己的订阅，作为编程子代理，不做反代、不给别人用。2026-11-03 按官方文档与条款核实

结论： 四家都提供官方认可的无浏览器/远程服务器登录方式，本人在自己服务器上用官方 CLI 属于正常用法。真正的红线是两条：不能把订阅凭证放进非官方软件（反代、第三方代理框架），不能给别人共用。

Claude：自用 Claude Code 与「第三方工具不能用订阅登录」的区别

允许

  • 在自己的服务器上运行未修改的官方 claude 程序，用自己的订阅登录
  • 官方原文：这些限制不妨碍用户用自己的订阅登录未修改的 Claude Code 程序
  • 派发服务只是启动官方 claude 进程，凭证留在 Claude Code 自己的存储里

禁止

  • 把订阅 OAuth 令牌放进 OpenClaw、Hermes 等非 Anthropic 的工具
  • 用 Agent SDK 自己写的程序走订阅额度（这类应使用 API Key）
  • 自建反代，把订阅额度转成 API 给别的程序或别人用
  • 第三方程序代为收集、保存、转手 Claude 登录凭证或会话令牌

两者不是一回事：此前说的禁令针对的是把订阅凭证用在 Claude Code 以外的软件上，而你的用法是本人运行官方程序。仍不确定的是无人值守高频调用的尺度，官方只说额度按普通个人使用设计，没有给出具体界限，所以设计上限定为本人触发、低并发。

  • 四家共同规则：只用官方 CLI 二进制，不改程序，不抽取令牌给其他软件；每家一个专用 worker 容器，凭证卷权限 600，任务沙箱不挂载凭证。
  • 只对管理员本人开放；另外 2–3 位注册用户的编程任务一律走按量 API Key。
  • 出现异常登录或额度异常时，先在官网吊销会话，再在服务器上 logout 并删除缓存凭证。

  • 阶段 2 · 主动推送：晨报、复盘、周战略、断档提醒，全部只读
  • 阶段 3 · MCP 接入个人系统：先只读，审计与一键停机就绪后再开写操作
  • 阶段 4 · 编程子代理：网关、派发服务、gVisor 沙箱，PR 交付
  • 阶段 5 · 个人管理界面：管理系统看板与对话融合，仍以网页和 PWA 交付

运维与每周维护

每周维护清单（约 15–20 分钟）

步骤 做什么 约用时
1. 看监控 外部监控里本周的可用性，有没有没处理的告警 2 分钟
2. 更新 确认系统安全更新已自动装好、是否需要重启；查看所用镜像的新版本和安全公告，发布满 3–7 天且没出问题的再按新摘要升级（升级前先备份） 4 分钟
3. 看日志和告警 失败登录次数、CrowdSec 封禁、新设备登录、MCP 写操作审计、编程任务记录、出站被拒记录 4 分钟
4. 核对备份 最近一次快照时间、快照数量有没有异常（防伪造快照）、备份心跳是否正常 2 分钟
5. 检查 API 用量 各供应商后台本周花费、余额、是否接近上限；订阅额度有没有异常消耗 3 分钟
6. 检查登录会话 LibreChat 活动会话、Tailscale 设备列表、Cloudflare Access 记录、各订阅官网的设备和会话列表，陌生的立即吊销 3 分钟
7. 扫一眼并登记 磁盘和内存用量、域名和证书到期时间；在维护日志里记一行（用于「无人值守降级」计时） 1 分钟

每月深度检查（约 1 小时）

  • 恢复演练：把最新备份恢复到临时环境，确认能登录并看到数据，然后销毁临时环境。
  • 停机演练：走一遍一键停机，以及云厂商控制台关机的步骤。
  • 外部端口扫描：从另一台机器扫描 VPS，确认没有预期外的开放端口。
  • 用户与权限：用户列表、角色、MCP 工具权限、未使用的邀请链接。
  • 密钥：各供应商后台的 Key 列表，删掉不用的；每季度轮换一次。
  • 订阅 CLI 重新登录一次；复查出站白名单和出站日志。
  • 框架健康：所用项目有没有停更、重大安全公告、收购或许可证变化。
  • 每季度加做：复核四家订阅条款和 API 地区政策；检查域名注册商、Cloudflare、邮箱、云厂商账号的 2FA；检查纸质恢复包。

出事时的应急清单

  1. 止损：触发一键停机；后台打不开或怀疑服务器已被控制，直接在云厂商控制台关机或断网。
  2. 吊销：各模型供应商后台吊销全部 API Key；四家订阅官网登出全部会话；吊销 Git 令牌、Tailscale 节点、Cloudflare Tunnel 令牌；重置所有用户密码并强制重新登录。
  3. 保全证据：先给磁盘做快照，导出审计日志和访问日志，不要急着删。
  4. 判断范围：从审计日志确定开始时间、动了哪些数据、哪些密钥可能泄露；检查 API 账单有没有异常调用。
  5. 重建：不在原机上「清理」，新开一台机器，从入侵前的备份恢复，所有密钥换新，镜像按已知安全的摘要重新拉取。
  6. 通知：涉及其他用户的数据就告诉他们；有盗刷就联系供应商申诉。
  7. 复盘：写下原因和修复，补进风险清单。

风险与待定问题

  • 订阅 CLI 已核实：四家都提供官方的服务器/无浏览器登录方式，本人自用可行；仍不确定的是无人值守高频自动调用的尺度，按低频、本人触发执行。
  • LibreChat 是否有关闭管理员查看他人聊天的开关，需部署时确认。
  • LibreChat 定时对话仍属实验功能，稳定性未知，必要时自写定时服务。
  • 你已有的个人管理系统用什么技术栈、数据库，决定 MCP 服务器的写法。
  • 另外 2–3 位用户是谁、能否接受管理员技术上可见其数据。
  • VPS 选哪家、哪个机房，影响国内电信与移动访问质量。
  • 你的手机有没有 Chrome 和 Google 服务，决定用 PWA 还是 TWA，以及通知怎么收。
  • 模型 API 账号的注册地和付款方式是否会被判定为不支持地区：不确定。
  • 外部监控服务选哪家（只需要心跳和可用性检测）。
