# Personal AI OS v2.0 交付手册

> 用途：让新的 AI、开发者或维护者能够快速接手本项目。  
> 当前核对基线：2026-09-09。  
> 当前形态：本地单用户 Windows 应用；不以公网部署为当前目标。

---

## 1. 先记住项目的核心

Personal AI OS 不是一个聊天机器人套壳，而是三部分：

1. **数据库**：本机 SQLite，是所有任务、项目、财务、健康和复盘事实的唯一来源。
2. **钥匙**：MCP + Skill。MCP 提供受控工具，Skill 规定使用顺序、数据口径和安全边界。
3. **AI 管家**：优先是外部 Agent，也可以是软件内的对话工作台。它必须通过工具读取真实数据，不能凭对话记忆或自行编造数据。

最重要的原则：

- 业务数据在本地数据库，不在提示词快照里。
- Web、外部 Agent MCP、软件内 AI 管家必须共用同一套业务规则。
- AI 只能做明确授权范围内的结构化读写。
- 高风险操作交给人确认，AI 不能代替用户点击确认。
- 不直接打开 SQLite、不直接执行 SQL、不绕过 API/MCP 改数据。
- 除非用户明确授权，不新增业务数据库、字段、统计口径、页面板块或自动化行为。
- 用户看到的“任务正文”和“备忘”是两个字段，不能混用。

## 2. 当前交付结论

当前主体已经进入本地稳定使用阶段：

- SQLite、迁移、WAL、单写者锁已实现。
- 任务、独立周期任务模板、项目、想法、财务、健康、计划、复盘、归档已实现。
- 周期任务在本地服务启动时检查并补齐错过的发生日期。
- 周备份在启动时按本地周日锚点检查，最多保留 3 份。
- MCP stdio、Agent token、scope、工具目录、资源、审计和幂等写入已实现。
- 软件内 AI 管家走真实工具循环：读取真实数据，制定阶段/每日计划草案，用户确认后在项目范围内推进，按执行情况调整，并把复盘写入数据库。今日任务、计划和复盘统计只按执行日期 `due_date`。
- 未确认覆盖当天的阶段计划时，服务端拒绝管家/MCP 推进项目（更新项目、工作区、给任务关联项目）。创建空项目、独立任务、财务、健康和计划/复盘草稿仍允许。人工界面不受此限制。

- 计划页正文已复用任务页块编辑器：可用斜杠插入标题、待办、列表、引用，并在停止编辑约 0.8 秒后自动保存。

## 3. 新 AI 的推荐接手顺序

新 AI 第一次接手时按以下顺序阅读：

1. 本文件：确认项目目标、当前事实和禁区。
2. docs/CURRENT-STATE.md：看当前已落地能力和已知限制。
3. docs/MCP.md：看 MCP 资源、工具名和 Agent 边界。
4. docs/SECURITY.md：看 token、scope、审计、备份恢复和 UI-only 操作。
5. skills/paios/SKILL.md：这是 AI 实际操作时的总手册。
6. 按任务领域再读：
   - tasks-and-recurrence.md：任务和周期任务
   - finance.md：财务口径
   - health-and-reviews.md：健康和复盘
   - projects.md：项目管理
   - agent-setup.md：外部 Agent 接入
7. 修改代码前再读对应源码和测试，不要只按旧计划猜实现。

文档优先级：

1. 用户最近明确的业务口径。
2. 当前源码、测试和本文件。
3. CURRENT-STATE、MCP、SECURITY、skills/paios。
4. PLAN.md、DECISIONS.md 和 docs/plans/ 中的历史设计。

若文档与当前源码或用户最新要求冲突，以较新的事实为准，并在修改后同步文档。docs/plans/ 目录的第一版页面重构计划仅作历史参考，不能当作当前待办清单。

## 5. 数据目录和运行模式

### 5.1 正式本地数据

正式运行默认使用：

~~~text
%USERPROFILE%\.paios\
├─ paios.db
├─ backups\
├─ attachments\       视使用情况产生
└─ 其他运行状态文件
~~~

Windows 展开后通常类似：

~~~text
C:\Users\<用户名>\.paios\
~~~

不要把仓库中的 .data 当成正式数据库。.data 只用于开发、测试或隔离验证。

### 5.2 开发数据

从仓库根目录运行开发服务前，显式指定隔离目录：

~~~powershell
$env:PAIOS_DATA_DIR = ".data"
pnpm dev
~~~

开发网页地址：

~~~text
http://127.0.0.1:5173
~~~

生产 Web/服务统一地址：

~~~text
http://127.0.0.1:4738
~~~

默认只绑定 127.0.0.1:4738，除非显式开启非本机绑定。非本机绑定需要用户明确授权并完成额外安全评估。

### 5.3 三种运行方式

| 方式 | 用途 | 是否需要用户先启动软件 |
| --- | --- | --- |
| release/Personal-AI-OS.exe | 用户图形界面 | 直接双击即可 |
| release/Personal-AI-OS.exe --mcp | 外部 Agent 的生产 MCP | 不需要先打开图形界面，由 Agent 自动启动 |
| pnpm dev / pnpm start | 开发调试 | 仅开发者使用 |

生产 MCP 不需要 pnpm dev，也不需要手动运行 node ... serve。不要为了让外部 Agent 工作而长期启动一个额外 HTTP 服务。

## 6. 图形界面和功能结构

左侧固定导航：

- 任务：任务数据库、想法数据库、周期任务模板和任务详情。
- 项目：项目画廊；点进项目后进入单独的项目工作区。
- 财务：快捷记账、支出、收入、账户、筛选和汇总。
- 健康：日期健康记录，包括体重、睡眠、运动和自律。
- 计划与复盘：每日计划、阶段计划、每日复盘、阶段复盘。
- AI 管家：对话历史、归档、复制、图片和软件内模型工作台。
- 归档：各业务归档数据的筛选、恢复、删除和批量删除。
- 设置：API key、Agent token、连接测试和相关本地设置。

主界面在有待处理事项时显示注意力摘要，约每 5 分钟、窗口重新可见时刷新。管家页面打开期间约每 60 秒检查当前上午/下午/晚上；换时段会再自动检查一次，并把结果写入当日复盘草稿。软件关闭期间不能主动联系用户。

## 7. 业务数据口径

### 7.1 任务和想法

任务：

- 普通任务表是 tasks。
- 任务名称、任务日期、状态、归档请求、备忘 description、长正文 content 分开保存。任务日期（due_date）就是执行日期；没有 due_date 的任务是未安排日期任务。今日任务、计划选取和复盘统计只按 due_date；scheduled_date 只保留写入兼容，不能当成执行日期。
- 状态是 todo、done、cancelled；新任务默认 todo。
- 只有归档请求已勾选且状态为 done 或 cancelled 时，任务才自动归档。
- 任务详情页面可记录长正文。正文编辑器支持普通文本、一级标题、二级标题、待办、无序列表、有序列表、引用。
- 计划/任务正文可能以 version 1 的块 JSON 保存。显示时必须经过 RichTextBlockEditor 的解析或 richTextToPlainText，不要直接把原始 JSON 当用户内容显示。

想法：

- 想法与任务在同一任务板块中管理，不再要求用户进入独立的想法导航。
- 想法字段是归档请求 archive_requested、标题 title、正文 body、类型 category、紧急程度 urgency、处理状态 processed。
- 类型是 project、long_term、short_term。
- 紧急程度是 1–4，1 最紧急，默认 4。旧 Skill 中的 1–3 说明已经修正为 1–4。
- 归档请求已勾选且处理状态为已处理时才自动归档。
- 想法升级为任务会产生人类确认票，Agent 只能发起申请，不能批准。

### 7.2 周期任务

周期任务和普通任务是两个层次：

- 周期任务模板：定义任务名称、正文、备忘、起始日期、周期规则和启用状态。
- 普通任务实例：按照模板实际生成，进入普通任务数据库。
- 模板不是一条“已经创建的普通任务再绑定规则”，而是独立的模板记录。

安全执行逻辑：

1. 服务启动时按用户本地时区触发周期同步。
2. 同步根据模板版本和本地日期计算应有的发生日期。
3. 通过唯一发生台账防止重复生成。
4. 一次长时间未运行时，补齐所有错过且应生成的日期，而不是只补今天。
5. 修改模板正文/标题/备忘默认保留原周期锚点；修改规则或起始日期才会建立新的未来节奏。
6. 已经生成的普通任务不会被模板覆盖。
7. 用户手动删除已生成的普通任务会留下删除发生标记，后续启动不再把它重新生成。
8. 暂停模板时跳过暂停期间的日期。
9. 模板删除由图形界面执行；删除模板不会删除已经生成的普通任务和发生历史。
10. 跨月、跨年、闰日、重复启动、锁竞争和失败重试由服务端处理，Agent 不得自行计算并批量伪造实例。

排查周期任务时按以下顺序：

~~~text
task_recurrences_list
task_recurrence_get
task_recurrence_occurrences_list
task_recurrence_check
~~~

只有用户明确要求“修复/补齐周期任务”时，才调用 task_recurrence_check 的 repair=true。修复只允许服务端补缺，不允许删改已有任务。

### 7.3 项目

- 项目首页是画廊，不把项目详细设计全部塞在列表里。
- 点进项目后进入独立工作区。
- 常用属性有名称、类别、启动时间、状态、目标日期、目标结果、收益配置等。
- 项目创建使用三种简洁模板：小型项目、中型/阶段性项目、长期/大型项目；模板只初始化项目介绍和目标，不替 AI 擅自生成具体方案。
- 项目可标记为盈利项目。盈利项目会自动生成“项目收入”下的动态收入小项和快捷按钮；财务记录通过稳定的 project_id 关联项目，项目详情显示收入、支出和净额。
- 项目工作区包含独立的项目任务计划。计划任务只有勾选“加入待办”后才会创建普通待办；未加入待办的项目任务不代表当天必须执行。
- 已加入待办的项目任务与普通待办保持同步：待办完成、归档或删除后，项目计划中的活动项会移除，同时保留一条轻量进展记录。
- 项目详情还包含精简的进展历史，供每日/阶段计划、复盘和 AI 管家读取。
- 项目资料写入使用 project_workspace_update；可执行工作使用 tasks_create/tasks_update。
- “加入待办”、项目任务计划和进展历史主要在图形界面。MCP 没有单独的加入待办工具；外部 Agent 只能通过普通任务和项目工作区工具配合用户操作。
- 未确认覆盖当天的阶段计划时，管家/MCP 不能更新项目状态或工作区，也不能给任务关联项目。创建空项目工作区仍允许。
- AI 可以按用户明确要求帮助规划和构建项目，但不得因为一个建议就擅自创建项目、任务或里程碑。

### 7.4 财务：三个完全独立的数据库

当前财务口径必须牢记：

1. 支出：finance_expenses。
2. 收入：finance_incomes。
3. 账户流水：finance_account_entries；账户总额由 finance_accounts 和账户流水管理。

支出和收入是日常事件记录，**不代表资金从某个账户支出或进入某个账户**。普通支出不需要询问账户，不创建账户流水，不改变账户余额。账户是用户专门设立的资金用途池，单独管理存入和取出。

规则：

- 金额在数据库和工具中使用整数分，例如 10 元是 1000。
- 自然语言记账先调用 finance_quick_preview。
- 支出/收入确认日期、大项、小项、金额后，再调用对应 create 工具。
- 使用 finance_taxonomy 读取当前合法的大项/小项组合，不要凭记忆发明分类。
- 账户存入或取出必须明确账户、方向和金额，使用 finance_account_entry_create。
- 写完后用对应 list 或 finance_summary 回读验证。
- 财务、健康和复盘是长期记录，不走任务式自动归档。

典型例子：

~~~text
用户说：今日午饭 10 元
正确理解：今日、支出、10 元、日常消费/饭费
不应追问：钱从哪个账户支出
不应执行：创建账户取出流水
~~~

### 7.5 健康和复盘

健康：

- 是长期日期记录，不归档。
- 记录体重、上床、起床、睡眠时长、运动内容、运动分钟数、自律等。
- 睡眠时长由上床和起床时间计算或使用明确的已知值；不能凭空补值。
- 运动字段使用 exercise_note、exercise_minutes，不使用已经废弃的 cloud_content。

复盘：

- 每日复盘和阶段复盘都有独立详情页。
- 复盘内容是草稿，直到用户在图形界面完成最终确认，Agent 不能声称已经 final。
- 草稿应包含三部分：客观数据统计、数据分析、后续建议。客观事实和推测必须分开；可能的相关性不能写成确定因果。
- reviews_daily_generate / reviews_period_generate 根据真实数据生成草稿；时段检查结果必须写入当日复盘草稿，不能只留在聊天记录。
- 任务统计只按 due_date。缺少的任务、财务或健康记录要明确说“没有记录”，不能编造“完成情况”或“没花钱”。

### 7.6 计划

- 每日计划和阶段计划是两类独立记录。阶段计划表示一个时间周期（例如一周），不是项目计划，也不会自动拉任务列表。
- 生成每日计划（plans_generate）会按 due_date 选取应执行的任务，写入 daily_plan_items；这不是把所有任务无条件塞进计划正文。
- 管家制定阶段计划前应读取想法、上阶段复盘、财务、健康、项目状态、逾期和未安排任务，再用 period_plans_upsert 写成草案。
- 计划可归档、删除和自动保存。
- 计划正文与任务正文一样支持块编辑器。输入斜杠可选择一级标题、二级标题、待办、无序列表、有序列表和引用。
- 计划是草稿；不要把计划草稿当成用户已经确认的执行安排。确认每日计划或阶段计划是图形界面操作。
- 每日计划、阶段计划的预览应使用可读文本转换，不要直接展示保存用的 JSON。

### 7.7 短期归档数据清理

- 财务、健康、项目、周期任务模板、计划和复盘不参与自动归档清理。
- 目前自动清理范围仅为已归档任务、已归档想法和已归档对话。
- 主界面首次成功加载提醒摘要后，最多每 7 天检查一次；归档时间超过 180 天才会进入清理。
- 有候选数据时，系统先覆盖生成本周安全备份，再在事务中删除，并保留周期任务实例的删除记录。
- 自动保留规则属于系统预先授权的维护动作；Agent 没有调用清理接口、物理删除或确认票的权限。

## 8. MCP + Skill 接入

### 8.1 生产配置

在兼容 MCP 的外部 Agent 中，将 mcpServers 中的路径改成实际 EXE 路径：

~~~json
{
  "mcpServers": {
    "paios": {
      "command": "<项目路径>\\release\\Personal-AI-OS.exe",
      "args": ["--mcp"],
      "env": {
        "PAIOS_TOKEN": "<在 Personal AI OS 设置页面创建并复制的 Agent token>"
      }
    }
  }
}
~~~

说明：

- Windows JSON 的反斜杠必须转义；也可以使用客户端支持的正斜杠路径。
- Agent token 在设置页面创建、复制、轮换和撤销；原始 token 只在创建/轮换时显示一次，数据库只保存 hash。
- 配置后必须重新加载 MCP，并首先调用 system_status。
- system_status 的 database 必须是 ok，dataDir 必须是用户的 .paios 个人目录。
- 如果 dataDir 是仓库 .data，立即停止：这说明连到了开发库。
- 再调用 capabilities_get，用户问“你能做什么”时优先使用它返回的固定 answer，不要自行扩大能力清单。
- 外部 Agent 应加载仓库的 skills/paios/SKILL.md。若客户端支持项目 Skill，直接把 skills/paios 作为 Skill 来源；不支持时再把该文件内容作为系统规则提供给 Agent。
- 配置路径由具体 Agent 决定，不要凭空假设 Antigravity、Gemini 或其他客户端的配置文件位置。

生产模式的关键点：

~~~text
release/Personal-AI-OS.exe --mcp
~~~

这是无界面直接 MCP 模式。它自己打开用户的本地数据库，不需要图形界面、pnpm dev 或 4738 HTTP 服务先运行。

开发模式的 pnpm --filter @paios/server mcp 只是调试适配器，默认转发到 PAIOS_URL=http://127.0.0.1:4738。只有开发服务已经明确启动时才使用它。

### 8.3 Agent 操作协议

连接后：

1. system_status。
2. 检查 database、dataDir、timezone 和恢复状态。
3. capabilities_get。
4. 涉及今天时先 today_get。
5. 涉及具体领域时先读取对应 list/get。
6. 修改已有记录时尽量带最新 row_version。
7. 可能重试的写入必须提供 idempotency_key。
8. 写入后回读验证。
9. 发生 VERSION_CONFLICT、权限错误、恢复锁或不确定结果时停止猜测并说明现状。

幂等规则：

- 同一个意图的超时重试，复用同一个 idempotency_key。
- 新的有意写入才使用新的 key。
- 不确定是否成功时，不能为了“试一下”换新 key，否则可能重复创建数据。
- 服务会把成功的普通 Agent 写入按工具名和幂等键缓存，并写入审计。

固定回答规则：

当用户问“你能做什么”时：

1. 调用 capabilities_get。
2. 以 answer 为主要能力说明。
3. 不承诺物理删除、恢复备份、批准确认票、改 schema、修改设置或其他没有公开的权限。
4. 若 scope 不足，以当前返回的 scope-aware 能力为准。

## 9. AI 管家写入边界

普通写入可在用户明确下令后执行。创建空项目工作区、独立任务、财务、健康、计划草稿和复盘草稿不要求先确认阶段计划。若当前日期落在已确认的阶段计划内，项目范围内的普通推进也可以执行：

- 创建/更新任务，修改执行日期（due_date），拆分过大任务。
- 创建/更新项目资料和推进状态（idea/planned/active/done）。
- 创建/更新想法。
- 创建支出、收入或账户流水。
- 写入健康记录。
- 生成或更新每日/阶段计划草稿和复盘草稿，并把时段检查写入当日复盘。
- 创建或更新周期规则，但前提是用户明确要求周期行为；实例仍由系统生成。

以下操作不能由 Agent 直接完成：

- 批准确认票。
- 想法升级为任务的最终确认。
- 确认每日计划或阶段计划。
- 归档、恢复、批量清理或物理删除。
- 备份、恢复数据库。
- 修改 schema 或迁移。
- 修改 API key、Agent token 或系统设置。
- 把项目改为 paused 或 abandoned，或改变项目核心方向。
- 在没有覆盖当天的已确认阶段计划时，推进项目（关联项目任务、更新项目状态或工作区）。人工界面不受此限制。
- 把支出自动挂到账户流水。
- 把一条周期模板直接当成普通任务或自己计算发生实例。
- 声称复盘已最终确认。

遇到需要人工确认的返回：

~~~text
CONFIRM_REQUIRED
~~~

只告诉用户待确认事项、影响范围和下一步位置，然后停止，不要尝试调用 approval 接口。

## 10. 备份、恢复和审计

### 10.1 自动周备份

每次本地服务启动时：

1. 根据设置中的本地时区计算当前周日锚点。
2. 判断该锚点的 weekly-YYYY-MM-DD.db 是否存在且完整。
3. 没有则创建一致性 SQLite 快照。
4. 每类备份最多保留 3 份。
5. 备份失败不阻止服务启动，记录失败，下一次启动继续重试。

备份目录是用户数据目录下的 backups。备份使用临时文件、完整性校验和原子替换，避免把 WAL/SHM 残留当成可恢复主库。

### 10.2 恢复

图形界面的恢复是受保护流程。正常步骤是：

1. 在归档/设置相关的备份界面查看备份。
2. 选择通过完整性校验的备份。
3. 发起恢复请求。
4. 在图形界面确认。
5. 关闭同一数据目录的直接 MCP 进程。
6. 重启图形程序，让 pending restore 生效。

主库已经损坏、图形界面无法启动时：

~~~powershell
release\Personal-AI-OS.exe --restore-latest
~~~

运行前关闭所有 Personal AI OS 和直连 MCP 进程。程序会选择最近可用备份，保留损坏主库的安全副本。Agent 不得自行调用恢复接口。

### 10.3 审计

- Agent 普通写入记录 token/Agent/工具身份、动作、目标、结果和变更前后快照。
- API key、token、密码等敏感字段会脱敏并限制长度。
- /api/v1/audit 默认返回最近 200 条。
- 当前没有把“审计只保留多少天”作为自动清理机制；不要擅自增加审计删除策略。
- 审计是排查“谁改了什么”的依据，不能用聊天记录替代。

## 12. 常见故障排查

### 软件打不开或 127.0.0.1 拒绝连接

先区分运行模式：

- 直接双击 EXE：应由 EXE 自己启动本机 Web 服务。
- 开发页面 5173：必须有 pnpm dev 和 Vite。
- 生产页面 4738：必须有 pnpm start 或 EXE。

检查：

1. 是否启动了旧副本或错误目录中的 EXE。
2. 是否有 Personal AI OS 进程占用端口。
3. 是否拿了旧的 resources 文件夹覆盖新版本。
4. 是否存在数据库锁、迁移错误或 Node 子进程退出。
5. 读取启动日志和 /api/v1/system/status，不要直接猜原因。

### Unexpected token '<' ... is not valid JSON

这表示前端期待 JSON，但拿到了 HTML，通常是：

- Web 页面和 API 不是同一个启动模式。
- 5173 页面请求了未启动的 4738 服务。
- API 路径被开发服务器 fallback 成 index.html。

先关闭混用的开发/生产服务，重新选择一种运行方式。生产 EXE 直接使用时不需要 pnpm dev。

### MCP 读到的数据不对

优先排查：

1. Agent 是否调用了 system_status。
2. dataDir 是否为用户 .paios，而不是仓库 .data。
3. 是否使用了旧 token 或旧 EXE 路径。
4. “今天”是否先调用 today_get；具体日期是否传给 tasks_list。
5. 是否把任务正文、备忘或周期模板误读成普通任务。
6. 读取到的数据要以工具返回为准，不能用提示词记忆补齐。

### 周期任务没有今天的实例

按顺序读取：

1. task_recurrences_list：模板是否启用、下次日期、上次检查、错误。
2. task_recurrence_get：规则和起始日期。
3. task_recurrence_occurrences_list：今天是否已生成、跳过或被删除。
4. 必要时在用户明确要求修复后调用 task_recurrence_check repair=true。
5. 检查本地时区和服务启动时间。

不要手工创建一条“看起来缺失”的普通任务，避免破坏发生台账。

### 计划显示成一大段 JSON

这是显示层直接使用了 plan_text 原值。正确做法：

- 编辑时使用 RichTextBlockEditor。
- 预览时使用 richTextToPlainText。
- 老的纯文本计划仍应由解析器兼容。
- 不要为了修显示而直接改数据库内容。

### 财务记账口径不对

确认四件事：

- 金额是否从元转换为整数分。
- 大项和小项是否来自 finance_taxonomy。
- 是否错误询问了日常支出的账户。
- 是否错误创建了 finance_account_entries。

日常支出、日常收入和账户存取是三条独立业务线。

### Tauri 构建失败但 target 有 EXE

若失败位置是 NSIS/MSI 的文件移动或临时目录错误，先确认 target/release/paios-desktop.exe 是否已经生成。直接 EXE 可用于本地验证；安装包问题单独处理，不要因此覆盖或删除现有 release 文件。

## 15. 交付责任边界

这份手册的目标不是让新 AI“自由发挥”，而是让它知道：

- 哪些数据是真实的。
- 哪些工具可以调用。
- 哪些动作必须先读后写。
- 哪些动作必须由人确认。
- 发生错误时如何停下来、回读和恢复。
- 哪些看似合理的功能当前明确不做。

任何新功能都必须先说明影响的数据表、权限、备份/恢复、幂等、周期任务兼容性和测试方案，再等待用户授权。
