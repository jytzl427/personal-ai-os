# Personal AI OS 每日计划 Bento HUD 规范与标准模板

## 一、 核心设计定位
Personal AI OS 每日计划采用高信息密度、交互式 Bento HUD（抬头显示仪表盘）结构设计。
所有由 AI 生成或维护的每日计划必须严格遵循本规范的 Markdown 语法结构，确保系统前端（`ReadOnlyPlanCard`）能够精准解析并在桌面端渲染为具有交互勾选、进度统计、目标预警与快捷编辑的高质感卡片。

---

## 二、 交互铁律与架构约定
1. **两大核心板块（晨起两步极速闭环，直接开工）**：
   - **第一板块：项目临期节点预警与任务挖掘（主攻硬仗）**：侦察临期攻坚节点，拆解微切片行动；
   - **第二板块：全盘行动总清单（底盘指标 + 分类待办一网打尽）**：聚合财务、健康、微习惯与项目/例行待办，形成一站式行动清单。
2. **标准 GFM 待办语法**：
   - 所有打卡项与执行任务必须使用 `- [ ]`（未完成）或 `- [x]`（已完成）标准格式；
   - 用户在系统前端点击勾选框时，系统会自动实时反向更新对应行的 Markdown 标记并调用接口持久化保存；
3. **视觉强调与图标规范**：
   - 重点类别使用加粗与对应 Emoji 前缀（如 `**财务**：`、`**健康**：`、`**习惯**：`、`🎯 [项目名]`）；
   - 临期与攻坚重点使用 GitHub Alert 语法（`> [!IMPORTANT]` 或 `> [!WARNING]`）包裹，提升视觉层级。

---

## 三、 标准每日计划 Markdown 模板

```markdown
# {{YYYY-MM-DD}} 每日计划

## 一、 项目临期节点预警与任务挖掘（主攻硬仗）
> [!IMPORTANT]
> **临期节点预警**：
> - ⚠️ 【{{项目A名称}}】验收节点「{{节点名称}}」将于 **{{YYYY-MM-DD}}** 截止（仅剩 {{N}} 天）
> - ⚠️ 【{{项目B名称}}】验收节点「{{节点名称}}」将于 **{{YYYY-MM-DD}}** 截止（仅剩 {{N}} 天）
>
> **今日主攻切片**：
> - 今日核心突破点：{{针对项目A/B的核心攻坚任务，具体到可验证的微切片行动}}

## 二、 全盘行动总清单（底盘指标 + 分类待办一网打尽）

### 1. 生活底盘与指标打卡
- [ ] **财务**：今日日常餐饮午晚预算上限 ¥25.00，全天坚守 0 冲动消费，警惕外卖奶茶
- [ ] **健康**：晨起空腹称重记录，今夜守住 00:30 就寝底线（目标时长 7.5h）
- [ ] **习惯**：饮水打卡 6 杯、早晚彻底刷牙、工作每 45 分钟起立走动拉伸打断

### 2. 项目攻坚任务（主干硬仗）
- [ ] 🎯 [{{项目A名称}}] {{子任务/攻坚行动1}}（预计耗时 {{X}}h）
- [ ] 🎯 [{{项目A名称}}] {{子任务/攻坚行动2}}（预计耗时 {{Y}}h）
- [ ] 🎯 [{{项目B名称}}] {{子任务/攻坚行动3}}（预计耗时 {{Z}}h）

### 3. 例行维护与日常杂项
- [ ] 🛠️ [{{维护类项目名称}}] 周期轻量打卡与数据备份巡检
- [ ] 🧹 [生活事务] 清理工作台桌面与衣物整理（15分钟轻量收尾）
```

## 四、 阶段计划推进目标（🎯 阶段目标）规范

在制定或更新阶段计划（`stage-plans`）时，推进类项目板块必须明确给出该项目在本阶段的**工作量定额与核心交付目标**。

### 阶段计划中推进类项目的标准书写格式：
```markdown
### 🎯 {{项目名称}}
- 🎯 **阶段目标**：{{明确的工作量或版本目标，例如：完成 v1.0 架构与核心功能开发 / 完成全书第 1-5 章初稿精修}}
- **截止日期**：{{YYYY-MM-DD}}
- **关键验收节点**：
  - [ ] {{YYYY-MM-DD}}：{{验收节点1标题}}
  - [ ] {{YYYY-MM-DD}}：{{验收节点2标题}}
```

### 速览卡片自动渲染机制：
- 前端 `ReadOnlyPlanCard` 会自动检测并在项目下方渲染专属高亮的 **`🎯 阶段目标：{{目标描述}}`** 胶囊/卡片；
- 使整个阶段的攻坚成果与验收节奏一目了然，杜绝无目标拖延。
